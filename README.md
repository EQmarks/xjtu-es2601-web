## 一、这是什么

一个**纯静态**成果展示网站，不需要服务器、不需要数据库。

**核心亮点**：从首页和导航进入 `map3d.html` 的**红色足迹浮雕中国地图**。采用真实省界 SVG，展示 **19 个足迹地点、12 组地区足迹、26 个家乡城市（28 位同学）**；支持点选查看地址与素材来源。

地图固定浮雕视角，不显示南海附图。已区分集体研学、个人寻访、视频分享、返校宣讲、校史源起和意向活动。地图的**数据、样式和代码全部内嵌**，支持直接双击和断网打开。

地点清单保存在 `assets/data/map-locations.json`；为了离线打开，地图页内还嵌有同一份几何数据，**更新时须同步两处**。

**后期规划**：本站结构预留了扩展位，可平滑改造成**储能2601 班级官网**（详见"换肤"一节）。

## 二、技术栈

| 项 | 选择 | 原因 |
|---|---|---|
| 框架 | **无**（原生 HTML/CSS/JS） | 零依赖、双击即开、部署零成本 |
| 地图 | **真实省界 SVG + 原生 JS** | 矢量浮雕、地点点选、金色关联连线，无运行时外部依赖 |
| 相册 | **原生 JS + Canvas 无关** | 照片墙 + 灯箱，图片双尺寸懒加载 |
| 样式 | **CSS 变量主题** | 换肤只改 `:root` |
| 构建 | **无** | 改完直接刷新 |

## 七、换肤（红色 → 蓝色）

全站颜色**只引用 CSS 变量**。改 `assets/css/style.css` 顶部 `:root` 即可整体换肤：

```css
/* 当前：红色（团日主题） */
:root{
  --brand:#C8102E;        /* 主色·中国红 */
  --brand-deep:#8B0A1E;   /* 深红 */
  --brand-light:#E63A50;
  --brand-tint:#FFF1F3;
  --accent:#D4AF37;       /* 辅色·金 */
  --page-bg:#FAF7F5;      /* 暖白底 */
  ...
}

/* 蓝色主题（班级官网）—— 取消注释即切换
:root{
  --brand:#1A4D8F; --brand-deep:#0E2F5C; --brand-light:#2E6DB4;
  --brand-tint:#EFF5FC; --accent:#C9A227;
  --ch1:#1A4D8F; --ch2:#0E2F5C; --ch3:#2E6DB4; --ch4:#C9A227;
  --page-bg:#F5F7FA; --line:#E0E6ED;
}
*/
```

> 班徽（蓝青色）是独立素材，不随主题色变化。交大标准色保留为 `--xjtu-*` 变量备用。

## 八、本地预览

**方式一（最简单）**：双击 `index.html`
> ⚠️ 但地图页和活动列表需要 `fetch` 数据，`file://` 协议会被 CORS 拦截
> → 这两类页面必须用方式二

**方式二（推荐）**：
```bash
cd 03_展示网站
python tools/serve.py 8801
# 浏览器打开 http://localhost:8801
```
> `tools/serve.py` 会显式声明 `charset=utf-8`，避免浏览器猜错编码导致中文乱码

## 九、部署与推送

### 9.1 首次部署到 GitHub Pages

```bash
git config user.name  "你的名字"
git config user.email "你的邮箱"
git remote add origin https://github.com/<用户名>/<仓库名>.git
git push -u origin main
```

**然后**：仓库页 → `Settings` → `Pages` → Source 选 `Deploy from a branch` → 分支 `main`、目录 `/ (root)` → `Save`

等 1-2 分钟，访问 `https://<用户名>.github.io/<仓库名>/`

> 💡 也可用 **Cloudflare Pages**：支持**拖拽文件夹上传**（不用 git），`*.pages.dev` 国内可达性通常更好。

### 9.2 ⚠️ 推送被墙时的解决办法

**现象**：`git push` 报错 `Failed to connect to github.com:443` 或 `Recv failure: Connection was reset`

**原因**：不是域名被墙，而是** DNS 解析到的那一个 IP 被精准封锁**（IP 黑洞）。

诊断证据：
```
github.com  → 20.205.243.166   ❌ TCP 握手就超时（包被丢弃）
api.github.com → 20.205.243.168  ✅ 通
codeload.github.com → .165       ✅ 通
GitHub 其他前置 IP（140.82.112.3 等 14 个）  ✅ 全部可通
```

**解决办法：走本地转发代理**

`tools/git_proxy.py` 会启动一个本地 CONNECT 代理，自动挑选一个可用的 GitHub IP，
无视 DNS 解析结果：

```bash
# 1) 启动代理（保持窗口不关）
python tools/git_proxy.py 8899

# 2) 通过代理推送
git -c http.proxy=http://127.0.0.1:8899 push origin main
```

代理工作方式：
```
git → 127.0.0.1:8899 → 140.82.112.3:443 → GitHub
        （本地代理忽略 DNS，直连可用 IP）
```

**验证代理是否可用**：
```bash
curl -x http://127.0.0.1:8899 https://github.com/ -o /dev/null -w "%{http_code}\n"
# 应输出 200
```

**备选方案**：把 SSH 公钥加到 GitHub，改用 SSH 推送（`github.com:22` 端口通常可通）
```bash
ssh-keygen -t ed25519 -C "es2601-deploy"
# 把 ~/.ssh/id_ed25519.pub 内容贴到 https://github.com/settings/ssh/new
git remote set-url origin git@github.com:<用户名>/<仓库名>.git
git push origin main
```
